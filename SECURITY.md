# Security policy

NOVA Agent can read and write workspace files and run commands after user approval. Treat API keys, session data, workspace files, and command output as sensitive.

## Reporting a vulnerability

Please do not publish an exploitable vulnerability, API key, private workspace content, or a proof of concept that exposes other users in a public issue.

If GitHub shows **Security → Advisories → Report a vulnerability** for this repository, use that private reporting flow. Otherwise, contact the repository owner privately through the contact method on the [KING-919 GitHub profile](https://github.com/KING-919), and include a concise description, impact, affected version, and safe reproduction steps. Do not include real credentials or private project data.

We will acknowledge reports when possible and coordinate a fix before public disclosure. NOVA currently has no published support or response-time guarantee.

## Supported versions

Security fixes are prepared for the latest published release. Older releases may not receive updates; upgrade to the latest version when a fix is available.
